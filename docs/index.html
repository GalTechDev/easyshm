EasySHM

IPC zéro-socket pour Python.

Partagez des giga-octets par seconde entre processus directement via la RAM, avec un réveil au niveau du noyau en quelques dizaines de microsecondes. Aucun port, aucune pile réseau.

FONCTIONNALITÉS

Tout le nécessaire pour faire circuler des données entre processus, sans le réseau.

Vitesse matérielle

speed

Contournez entièrement la pile réseau : les processus lisent et écrivent les mêmes pages de RAM physique.

mmap ~35 µs

Signalisation noyau

notifications_active

Une écriture réveille d'un coup tous les processus en attente : futex sous Linux, Named Events sous Windows, sémaphores sous macOS. Pas d'attente active.

wait_update() on_update()

Auto-grow

open_in_full

Les segments se redimensionnent à la volée sans déconnecter les processus. L'auto-shrink optionnel libère la mémoire.

resize() on_resize()

Vues zéro-copie

grid_on

Mappez des tableaux NumPy, des tenseurs PyTorch ou des structures C directement sur le buffer partagé, ou enregistrez votre propre vue.

numpy torch struct

Process-safe

lock

Chaque accès passe par un mutex IPC et un verrou de thread. Les mutex abandonnés par un processus planté sont récupérés automatiquement.

mutex CRC32

Mémoire verrouillée

push_pin

Verrouillez optionnellement les segments en RAM physique pour que l'OS ne les swappe jamais, pour une latence prévisible.

mlock VirtualLock

DÉMARRAGE RAPIDE

  • play_arrow Tous les processus qui ouvrent le même nom partagent la même mémoire. Le premier la crée, les autres la rejoignent.
  • play_arrow write() réveille tous les processus en attente sur le segment.
  • play_arrow Les vues donnent un accès typé et zéro-copie : modifier le tableau modifie la mémoire partagée.
RÉFÉRENCE API COMPLÈTE arrow_forward

code quickstart.py 

from easyshm import EasySHM
import ctypes

# Crée ou rejoint un segment partagé
shm = EasySHM("my_data", size=1024)

# 1. Tableau NumPy (zéro-copie)
arr = shm.as_view("numpy", shape=(10,), dtype="float32")
arr[0] = 42.0

# 2. Structure C (zéro-copie)
class Point(ctypes.Structure):
    _fields_ = [("x", ctypes.c_int), ("y", ctypes.c_int)]

p = shm.as_view("struct", type=Point)
p.x = 100

# 3. Attendre une mise à jour d'un autre processus
if shm.wait_update(timeout=5.0):
    print(shm.read())

PERFORMANCE

Mesuré, pas promis : deux processus, des milliers d'allers-retours, comparés à un socket TCP local avec le même protocole.

Mesure EasySHM TCP localhost
Latence de réveil, aller simple (médiane / p99) 35 µs / 130 µs 17 µs / 80 µs
Aller-retour 1 Mo (médiane) ~170–190 µs ~110–160 µs
Diffusion vers N processus 1 écriture, tous réveillés d'un coup N envois
CPU au repos, segment ouvert 0 % 0 %

Linux (WSL2), Python 3.12, 12 CPU. La latence est dominée par Python lui-même : pour de tout petits messages, un socket local reste plus rapide. EasySHM brille quand plusieurs processus partagent le même gros état sans le renvoyer. Lancez python benchmarks/latency.py pour mesurer votre machine.
